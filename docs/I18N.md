# i18n — French, English, Arabic (RTL)

Supported languages: `fr`, `en`, `ar`. Arabic is right-to-left.

## 1. Source of truth

All UI strings live in [`src/i18n/translations.ts`](../src/i18n/translations.ts) as a flat object:

```ts
export const translations = {
  navMyBookings: {
    fr: 'Mes Réservations',
    en: 'My Bookings',
    ar: 'حجوزاتي',
  },
  // …
};
```

- Read a string with `getTranslation('navMyBookings', language)` or `translations.navMyBookings[language]`.
- `language` comes from `AppContext`; it is persisted in `localStorage` under `omnibook_lang` and defaults to `fr`.
- On change, `AppContext` sets `document.documentElement.lang` and `dir` (`rtl` when `ar`).

## 2. Non-negotiable rules

1. **No hardcoded user-facing string** in a component, error message, notification, validation message, accessibility label or push payload.
2. Every key must exist in **all three** languages and must not be empty.
3. Interpolation uses named placeholders and must be identical in every language:
   `'Réservation {id} confirmée'` → `'Booking {id} confirmed'` → `'تم تأكيد الحجز {id}'`.
   Never build a sentence by concatenating fragments: word order differs in Arabic.
4. Plurals: use the language's plural rules, never `count === 1 ? … : …`. Arabic has six forms
   (zero, one, two, few, many, other).
5. Format dates, numbers and currencies with `Intl` (`Intl.DateTimeFormat`, `Intl.NumberFormat`),
   not with manual concatenation.

## 3. RTL checklist (Arabic)

- Layout uses **logical properties**: `margin-inline-*`, `padding-inline-*`, `inset-inline-*`, `text-align: start`, `border-start-*`. Avoid `left` / `right` for layout.
- Mirror directional icons (back, forward, chevrons, send). Do **not** mirror logos, media controls, clocks or phone numbers.
- Wrap mixed-direction fragments (URLs, Latin brand names, card serial numbers) in `<bdi>` / `dir="auto"`.
- The app shell and legal pages must declare `dir="rtl"` for Arabic (`public/privacy/ar/`, `public/delete-account/ar/`).
- Arabic needs more line height than Latin; never apply letter-spacing to Arabic text.
- Test layouts with French (≈20–30 % longer than English) and Arabic (taller) before merging.

## 4. Adding a string

1. Add the key with `fr`, `en` and `ar` values in `src/i18n/translations.ts`.
2. Use it through `getTranslation(key, language)`.
3. Run the parity gate:

```bash
npm run i18n:check
```

The gate (`scripts/check-i18n.ts`) fails on:

- a key missing `fr`, `en` or `ar`;
- an empty or whitespace-only value;
- an unsupported language key;
- placeholders that differ between languages.

CI runs the same command in `.github/workflows/quality-checks.yml` (job *Regression tests*),
so a missing translation blocks the merge.

## 5. Known gaps

- Some screens still branch on `language === 'fr' ? … : …` inline instead of using translation
  keys. New code must not add more of these; migrate the ones you touch.
- The default language is currently `fr` (not `en` as `AGENTS.md` recommends). Changing it
  affects existing users' persisted preference and should be decided by the owner.
